## Design Context

### Users

Swedish SMB owners and marketing managers (1-20 employees) who arrive **frustrated** with their current website. They know something is wrong but lack the technical knowledge to diagnose it. They may be anxious about GDPR/accessibility compliance, or simply tired of an aging WordPress site that isn't performing.

After using Vivotiv, they should feel **relief** -- a weight lifted because they now have a clear, actionable path forward. Not overwhelmed with technical jargon, but empowered with specific next steps.

**Key emotional arc:** Frustrated and uncertain --> Clarity and relief --> Confidence to act

### Brand Personality

**Relief. Trustworthy. Helpful.**

Vivotiv speaks like a knowledgeable friend who happens to be a web expert. Not a salesperson, not a lecture. It identifies problems honestly, explains them plainly, and shows the way forward without pressure. The tone is warm but precise -- every word earns its place.

- Never condescending or overly technical
- Never vague or hand-wavy
- Never pushy or fear-mongering (even when discussing fines and compliance)
- Always specific, always honest, always useful

### Aesthetic Direction

**Visual tone:** Restrained confidence. Clean, structured, and professional with warmth from the golden/orange brand accent. Light mode primary. Sharp corners signal precision and seriousness. The design should feel like a well-organized diagnostic report, not a marketing brochure.

**Current base (keep and build on):**
- OKLch color system with warm-tinted neutrals
- Geist (body) + Space Grotesk (headings)
- Sharp corners (0 radius)
- Monochrome palette with warm orange/golden brand accent
- Scroll-triggered motion via motion/react

**Reference sites and what to take from them:**
- **Polar.sh**: Spacious layouts, restrained motion (cubic-bezier, not bounce), trust through clarity and transparency, multiple font levels creating distinct hierarchy
- **Stripe**: Generous whitespace as a trust signal, asymmetrical layouts that feel intentional, precision alignment, professional without being cold
- **Rocket.new**: Structured bordered sections, concrete credibility signals (certifications, metrics), purposeful whitespace that conveys stability
- **OpenRouter**: Concrete metrics displayed prominently, snappy transitions (200-400ms), responsive type scaling, card depth through subtle shadow progression (not glow)

**Anti-references (what Vivotiv must NOT look like):**
- Generic AI slop: glow orbs, pulsing badges, cyan-on-dark, purple gradients, glassmorphism
- Cookie-cutter SaaS: identical card grids, hero metric layouts, rounded-everything
- Enterprise bloatware: dense, overwhelming, feature-dump layouts
- Flashy startup: animation-heavy, attention-grabbing for its own sake

### Accessibility

- **Target: WCAG AA minimum**, with AAA where achievable (especially contrast ratios)
- High accessibility is a core requirement, not an afterthought -- Vivotiv literally audits others for accessibility
- Reduced motion: respect `prefers-reduced-motion` media query; disable non-essential animations when set
- Semantic HTML throughout, proper heading hierarchy, ARIA labels on all interactive elements
- Focus indicators must be visible and clear
- All interactive targets minimum 44x44px on touch devices

### Design Principles

1. **Clarity over cleverness.** Every element should reduce confusion, not add decoration. If a visual choice doesn't help the user understand their situation or next step, remove it.

2. **Earned trust through precision.** Exact numbers, specific issues, real consequences. The design reflects this: precise alignment, consistent spacing, deliberate typography. Nothing sloppy, nothing approximate.

3. **Warmth without softness.** The golden brand accent, warm-tinted neutrals, and helpful tone create approachability. But sharp corners, tight copy, and structured layouts maintain authority. Friendly expert, not friendly amateur.

4. **Progressive disclosure.** Start with the headline finding, let users dig deeper. Never dump everything at once. The frustrated user needs relief first, details second.

5. **Show, don't decorate.** Motion serves information (revealing content, indicating state changes, guiding attention). Decoration serves ego. Every animation must answer: "what does this help the user understand?"
